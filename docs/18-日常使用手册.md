## 1. 服务状态检查与启停

| 服务 | 检查 | 启动 | 停止 |
|------|------|------|------|
| nginx（:80 入口） | `systemctl status nginx` | `sudo systemctl start nginx` | `sudo systemctl stop nginx` |
| Strapi（:1337 后台/API） | `systemctl --user status strapi-b2b` | `systemctl --user start strapi-b2b` | `systemctl --user stop strapi-b2b` |
| webhook-listener（:1340 预览/重建） | `systemctl status b2b-webhook` | `sudo systemctl start b2b-webhook` | `sudo systemctl stop b2b-webhook` |
| PostgreSQL | `systemctl status postgresql` | — | — |
| 定时任务 | `crontab -l` | — | — |

> **Strapi 已于 2026-09-08 改为 systemd 用户服务**（`~/.config/systemd/user/strapi-b2b.service`），并已开启 linger（`loginctl enable-linger ssyin`），服务器重启后**自动拉起，无需登录、无需手动操作**。日志用 `journalctl --user -u strapi-b2b -f` 查看（旧的 `strapi-restart.log` 不再使用）。
> 验证整体健康：浏览器打开 `http://<IP>/`（首页）、`http://<IP>/admin/`（后台）均正常即通。

## 2. 后台内容管理

后台地址 `http://<IP>/admin/`。默认中文界面，账号由 Strapi 管理员体系维护。

### 2.1 设备（Equipment）管理

**新建设备**（内容管理 → Equipment → 创建新条目）：

1. **slug**：URL 别名，小写英文+连字符（如 `c-type-jaw-crusher`），全站唯一；重复时构建只保留第一台并在日志报错。**创建后不建议随意修改**——改 slug 会产生旧链接 404（如需保留旧链接，见 §2.1 末尾 legacy 映射）。
2. **基本信息**：中英文名称、分类（mobile/crushing/screening/washing/parts 五类，决定目录页归属）。
3. **图片**：`images` 多图（第一张为封面）、`og_image` 分享封面。
4. **正文**：中英文简介、特点（features 列表）、`content` Dynamic Zone（富文本/图片/图册/列表/表格/参数表分节，可拖动排序）。
5. **型号参数表**：`model_tables_grid`（可视化网格编辑：加列、加行、填备注，无需碰 JSON）。
6. **SEO**：`seo_title_*` / `seo_description_*` 留空时自动用设备名/简介兜底。
7. 保存 → 点**发布**（或先存草稿用预览检查，见 §3）。

**发布/取消发布**：条目列表或编辑页右上角按钮。**取消发布 = 前台下架**（下次构建不再生成该页，但后台数据保留）；**删除 = 数据彻底移除**，下次构建会把中英文页面一并清掉（PRUNE 自动清理）。

**修改内容后多久生效**：保存/发布/删除后约 **3 秒**自动触发重建，构建几秒到十几秒完成。可 `tail -f /var/www/B2B/auto-rebuild.log` 观察「重建完成」。

**改 slug / 旧链接保留（legacy 映射）**：把旧 slug → 新 slug 的映射加入 `data/legacy-equipment-slugs.json` 的 `redirects`，并在 nginx 站点配置（`/etc/nginx/sites-available/minelink`）加一条 `location = /equipment/旧slug.html { return 301 /equipment/新slug.html; }` 后 `sudo nginx -s reload`。这样旧 HTML 文件会被保留、搜索引擎与历史链接自动跳新页。

### 2.2 站点设置（Site-setting）

站点中英文名称与描述——影响各页面标题/页脚与 SEO。修改后约 3 秒自动重建生效（cron 每 30 分钟兜底）。

### 2.3 网站图片（Website-image）

按「槽位」管理首页/内页各位置图片：选槽位（page+position）、上传图、填 alt、`enabled` 开关。详细操作见 [16-网站图片运营操作手册](./16-网站图片运营操作手册.md)，技术机制见 [15-网站图片管理技术文档](./15-网站图片管理技术文档.md)（这两份仍为当前有效文档）。

## 3. 草稿预览

两个入口，看到的都是**未发布的草稿内容**（页面顶部有「草稿」横幅、noindex）：

- **后台原生预览**：设备编辑页右上角「Preview / 预览」→ 弹窗内嵌 iframe。
- **「打开草稿预览」按钮**：编辑页右侧面板（equip-editor 插件注入）→ 新标签页整页打开。

**常见提示**：

- iframe 显示「该内容被屏蔽了」→ CSP 配置问题，确认 `backend/config/middlewares.js` 的 `frame-src` 含 `'self'` 且 Strapi 已重启（2026-09-07 已修复，正常不应再出现）。
- 显示「登录已过期」→ 后台 JWT 约 30 分钟有效期，回后台刷新/重新登录后再点预览。
- 「预览页」标签（非草稿）→ 显示的是线上已发布静态页，属正常设计。

## 4. 内容变更如何生效（重建机制速记）

| 触发 | 时机 | 说明 |
|------|------|------|
| 自动（主链路） | 后台对设备的增/改/发布/删除后 3 秒 | lifecycle 钩子执行，日志 `auto-rebuild.log` |
| cron 兜底 | 每 30 分钟 | API 内容哈希与 `.content-hash` 不同才重建；**「创建后又删除」这类净零变化不会触发** |
| 手动 | 随时 | `node scripts/build-pages.js`（项目根目录执行） |

手动构建参数：`--no-prune` 临时关闭过期页清理；`--api-base <url>` 覆盖 API 前缀（一般用不到）。

## 5. 询盘（Inquiry）处理

1. **查看**：后台 → 内容管理 → Inquiry。字段含意向设备、客户姓名、邮箱、WhatsApp、国家、留言、提交时间、邮件状态（`email_sent` / `mail_status`）。
2. **每封邮件的发送日志**：后台 → Maillog，按时间倒序查；失败记录带 `error_message`。
3. **没收到邮件时**：先查 Maillog 的错误信息；常见原因是 SMTP 未配置/密码错（配置在 `backend/.env` 的 `SMTP_*` 与 `SALES_EMAIL`，改后需重启 Strapi）。
4. **重发邮件**（不新建询盘记录）：

```bash
RETRY_KEY=$(grep '^RETRY_KEY=' /var/www/B2B/backend/.env | cut -d= -f2-)
curl -X POST http://127.0.0.1/api/inquiry/resend \
  -H "Content-Type: application/json" \
  -H "x-retry-key: $RETRY_KEY" \
  -d '{"documentId":"<询盘的 documentId，后台条目 URL 里可查>"}'
```

重发结果同样记录在 Maillog。

## 6. 服务器 IP / 端口变更

**先记住结论**：站点地址是**运行期动态生成**的（`{{ORIGIN}}` 占位符 + nginx `sub_filter` 替换，原理见 17 号手册 §5.5），静态页和 sitemap 里不保存任何绝对地址。

### 6.1 各场景操作矩阵

| 变化场景 | 需要做的操作 |
|----------|-------------|
| 服务器 IP 变了（DHCP/换机房/重新拨号） | **无需任何操作**，直接用新 IP 访问 |
| 换域名 / 上 DDNS（如 duckdns 指向新 IP） | **无需任何操作**，DNS 解析过去即可 |
| 访问端口变了（nginx `listen` 需要改） | 改 `/etc/nginx/sites-available/minelink` 的 `listen 80;` → `sudo nginx -t && sudo systemctl reload nginx`，其余自动适配 |
| http → https | 需申请证书并改 nginx 配置，属于独立改造，不在本节范围 |

### 6.2 变更后验证清单（可选，30 秒）

```bash
# 用任意假 IP:端口 模拟访客访问，页面内地址应自动跟随
curl -s -H "Host: 203.0.113.7:9999" http://127.0.0.1/sitemap.xml | grep -m2 '<loc>'
curl -s -H "Host: 203.0.113.7:9999" http://127.0.0.1/equipment/crawler-jaw.html | grep -o -m1 'rel="canonical"[^>]*'
# 两条输出都应显示 http://203.0.113.7:9999/... ；若出现 {{ORIGIN}} 字面量说明绕过了 nginx（见 §8 排障）
```

浏览器直接打开新地址看首页、后台（`/admin/`）、任一设备页正常即可。

### 6.3 ⚠️ 不要再运行 scripts/update-site-url.sh

该脚本属于**旧方案**（把绝对地址写进 `.env` 的 SITE_URL 并重新构建），现在运行它**反而会破坏动态机制**：构建产物会被写死成脚本参数里的地址，下次 IP 再变时全站 canonical/sitemap 都指向旧地址。

误运行后的恢复方法：

```bash
cd /var/www/B2B
sed -i 's|^SITE_URL=.*|SITE_URL=|; s|^CLIENT_URL=.*|CLIENT_URL=|' backend/.env   # 清空两行
node scripts/build-pages.js                                                       # 重建（产物恢复 {{ORIGIN}} 占位符）
```

### 6.4 后台预览与询盘

后台「预览」按钮的 URL 由 Strapi 运行时取访问 Host 动态拼出，询盘表单走同源相对路径——两者都与 IP/端口无关，变更地址后无需处理。

## 7. 备份与恢复

- **自动备份**：每周日 03:00 由 cron 执行 `scripts/backup-db.sh`，产出 `backups/db/strapi_db-<时间戳>.sql.gz`（权限 600，保留 56 天，日志 `backups/db.log`）。
- **手动备份**：直接运行 `bash scripts/backup-db.sh`。
- **恢复**：

```bash
gunzip -c backups/db/strapi_db-XXXX.sql.gz | \
  PGPASSWORD=<DATABASE_PASSWORD> psql -h 127.0.0.1 -U strapi_user -d strapi_db
node scripts/build-pages.js   # 恢复后重建静态页
```

## 8. 故障排查速查

| 症状 | 原因 | 处理 |
|------|------|------|
| 后台/首页 502 | Strapi 未运行 | `systemctl --user start strapi-b2b`；日志 `journalctl --user -u strapi-b2b -n 50` |
| 改了内容前台没变 | 自动重建失败 | `tail auto-rebuild.log`；手动 `node scripts/build-pages.js` |
| 删除设备后页面还在 | 构建未跑或 PRUNE 被关 | 同上；确认没有用 `--no-prune` |
| 预览 iframe 被屏蔽 | CSP frame-src 缺 'self' | 检查 `backend/config/middlewares.js` 并重启 Strapi |
| 预览提示登录过期 | JWT 30 分钟失效 | 回后台重新登录 |
| 询盘没收到邮件 | SMTP 配置/服务问题 | 查 Maillog 错误；用 §5 命令重发 |
| 页面里出现 `{{ORIGIN}}` 字面量 | 绕过 nginx 直接访问了文件（或 nginx 配置丢失 sub_filter） | 确认通过 nginx 入口访问；检查 `/etc/nginx/sites-available/minelink` 的 `sub_filter` 三行（原理见 17 号手册 §5.5） |
| canonical/sitemap 显示旧 IP 或旧域名 | `backend/.env` 的 SITE_URL 被设置过（如误运行 update-site-url.sh） | 按 §6.3 恢复：清空 SITE_URL/CLIENT_URL 后重建 |
| 图片不显示 | 槽位未启用/图片未传 | 后台 Website-image 检查 `enabled` |
| 旧链接 404 | slug 改名未配 301 | 按 §2.1 配 legacy 映射 + nginx 301 |

## 9. 常用命令速查

```bash
# 服务（Strapi 为 systemd 用户服务，已开机自启）
systemctl --user status strapi-b2b                # Strapi 状态
journalctl --user -u strapi-b2b -f                # Strapi 实时日志
systemctl --user restart strapi-b2b               # 重启 Strapi（改 .env 后执行）
sudo systemctl restart b2b-webhook nginx          # 重启预览/重建服务、nginx

# 构建
node scripts/build-pages.js                       # 手动全量重建
tail -f auto-rebuild.log webhook-listener.log     # 看重建日志

# 内容检查
curl -s http://127.0.0.1/api/equipments | head -c 300             # API 存活
ls equipment/*.html | wc -l && ls en/equipment/*.html | wc -l     # 已生成页面数

# 数据库备份
bash scripts/backup-db.sh
```

> ✅ 全部常驻组件（nginx、PostgreSQL、b2b-webhook、strapi-b2b）均已 systemd 托管并开机自启，服务器重启后无需任何手动操作。
