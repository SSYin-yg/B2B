# 10 - 生产环境部署手册（当前架构）

> 📌 **状态（2026-09-07）**：已按当前真实部署重写（原 PM2 + GitHub Pages 方案已废弃）。
> 本文既是现状记录，也可作为**新服务器迁移手册**。原理详见 [17-系统架构文档](./17-系统架构文档.md)。

## 一、部署架构（现状）

单台 Linux 服务器承载全部组件，nginx :80 是唯一公网入口：

| 服务 | 运行方式 | 端口 | 配置位置 |
|------|---------|------|---------|
| nginx 1.28 | systemd | 80（公网） | `/etc/nginx/sites-available/minelink` |
| Strapi 5.52.3 | systemd 用户服务 `strapi-b2b.service`（linger 开机自启） | 1337（本机） | `/var/www/B2B/backend/.env` |
| webhook-listener | systemd `b2b-webhook.service` | 1340（本机） | `/etc/systemd/system/b2b-webhook.service` |
| PostgreSQL 17 | systemd | 5432（本机） | 库 `strapi_db` / 用户 `strapi_user` |
| cron（用户 ssyin） | crond | — | `crontab -l`（重建兜底 + 备份） |

环境要求：Node.js ≥ 20（当前 v24.20.0）、Ubuntu（内核 6.17）、2 GB 内存即可。

## 二、nginx 站点配置要点

`/etc/nginx/sites-available/minelink`（符号链接到 sites-enabled，改后 `sudo nginx -t && sudo systemctl reload nginx`）：

```nginx
server {
    listen 80 default_server;
    server_name _;

    # === 安全屏蔽（2026-09-08 已应用；重装时可运行 scripts/harden-nginx.sh 自动添加） ===
    # 点文件：/.git/ /.git.old/ /.env /.content-hash 等
    location ~ /\. { deny all; access_log off; log_not_found off; }
    # 项目内部目录：后台代码、数据库备份、脚本、数据、内部文档
    location ^~ /backend/ { deny all; }
    location ^~ /backups/ { deny all; }
    location ^~ /scripts/ { deny all; }
    location ^~ /data/    { deny all; }
    location ^~ /docs/    { deny all; }
    # 敏感后缀：日志 / 数据库 dump / 脚本 / 备份
    location ~* \.(log|sql|gz|sh|bak|save)$ { deny all; access_log off; }

    # 草稿预览 → webhook-listener
    location /preview/ {
        proxy_pass http://127.0.0.1:1340;
        # 需传递 Host 与 WebSocket 升级头（按现有配置保留）
    }

    # 重建触发 → 仅本机（公网请求 403）
    location /rebuild {
        allow 127.0.0.1;
        deny all;
        proxy_pass http://127.0.0.1:1340/rebuild;
    }

    # 旧 slug 301（与 data/legacy-equipment-slugs.json 对应，共 19 条）
    location = /equipment/c-jaw.html { return 301 /equipment/c-type-jaw-crusher.html; }
    # ...其余 18 条同格式

    # 静态站点（location /）与 Strapi 反代（/api/ /admin/ /uploads/
    # /content-manager/ /users-permissions/ 等 → 127.0.0.1:1337）
    location / { root /var/www/B2B; try_files $uri $uri/ =404; }
    location /api/ { proxy_pass http://127.0.0.1:1337/api/; }
    # ...完整配置以服务器实际文件为准
}
```

> ✅ 安全屏蔽已于 2026-09-08 应用到本服务器（`sudo bash scripts/harden-nginx.sh`，幂等可重复执行，含备份/回滚/自检）。上面样例已包含该块，重装时照抄即可。
> 注意：`location ~ /\.` 会连带屏蔽 `/.well-known/`——将来若上 Let's Encrypt 证书（HTTP-01 验证），需为 `/.well-known/acme-challenge/` 单独放行。

## 三、webhook-listener systemd 服务

`/etc/systemd/system/b2b-webhook.service`（已部署，`Restart=always` 自动拉起）：

```ini
[Unit]
Description=B2B Webhook Listener (auto-rebuild frontend on Strapi content change)
After=network.target

[Service]
Type=simple
User=ssyin
WorkingDirectory=/var/www/B2B
ExecStart=/usr/bin/node /var/www/B2B/scripts/webhook-listener.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now b2b-webhook
```

## 四、定时任务（crontab -e，用户 ssyin）

```cron
*/30 * * * * /bin/bash /var/www/B2B/scripts/auto-rebuild.sh >> /var/www/B2B/auto-rebuild.log 2>&1
0 3 * * 0 /var/www/B2B/scripts/backup-db.sh >> /var/www/B2B/backups/db.log 2>&1
```

## 五、从零部署 / 迁移到新服务器

```bash
# 1. 基础软件
sudo apt install -y nginx postgresql nodejs npm   # Node ≥ 20

# 2. 代码
git clone <repo_url> /var/www/B2B && cd /var/www/B2B
(cd backend && npm install)

# 3. 数据库
sudo -u postgres psql -c "CREATE USER strapi_user WITH PASSWORD '<强密码>';"
sudo -u postgres psql -c "CREATE DATABASE strapi_db OWNER strapi_user;"

# 4. 配置 backend/.env（密钥全部重新生成，见 09-环境变量配置说明）
cp backend/.env.example backend/.env && vim backend/.env
cp backend/.env.example ../.env 2>/dev/null || true   # 根目录 .env 同步 SITE_URL/STRAPI_URL

# 5. 首次构建 admin + 启动（systemd 用户服务 + linger 开机自启）
cd backend && npm run build && cd ..
mkdir -p ~/.config/systemd/user
cp /var/www/B2B/docs/strapi-b2b.service.example ~/.config/systemd/user/strapi-b2b.service  # 本服务器上已有现成文件
loginctl enable-linger ssyin                       # 未登录也随开机拉起用户服务
systemctl --user daemon-reload && systemctl --user enable --now strapi-b2b
journalctl --user -u strapi-b2b -f                 # 观察启动日志，打开 /admin 创建管理员

# 6. nginx + webhook + cron
sudo cp <站点配置> /etc/nginx/sites-available/minelink
sudo ln -s /etc/nginx/sites-available/minelink /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl enable --now b2b-webhook             # 服务文件见 §三
crontab -e                                          # 加入 §四 两行

# 7. 数据恢复（如有备份）+ 首次全量构建
gunzip -c backups/db/strapi_db-*.sql.gz | PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db
node scripts/build-pages.js
```

**防火墙建议**：公网只放行 80/443 与 SSH；1337/1340/5432 保持仅本机访问（Strapi HOST 虽为 0.0.0.0，但不应从公网可达）。

## 六、IP / 端口变更流程

站点地址为运行期动态生成（`{{ORIGIN}}` 占位符 + nginx sub_filter，见 17 号手册 §5.5）：

- **仅换 IP / 换域名 / DDNS**：无需任何操作；
- **端口变化**：修改 nginx `listen` 后 `sudo nginx -t && sudo systemctl reload nginx` 即可。

验证方法与旧脚本 `update-site-url.sh` 的废弃说明见 18 号手册 §6。

## 七、日常运维 Checklist

| 频率 | 项目 |
|------|------|
| 每次服务器重启后 | 无需手动操作（nginx/PostgreSQL/b2b-webhook/strapi-b2b 均已 systemd 托管开机自启）；确认 `systemctl status nginx postgresql` 与 `systemctl --user status strapi-b2b` 正常 |
| 每周 | 确认 `backups/db/` 有新备份且非空；`backups/db.log` 无报错 |
| 每月 | 检查磁盘空间（uploads/备份）；查看 `auto-rebuild.log` 尾部有无持续失败 |
| 变更后 | 内容改动看 3 秒内是否自动重建；预览/询盘/后台各点一遍 |

## 八、灾难恢复

1. **代码**：git 仓库（github.com/SSYin-yg/B2B，私有）重新 clone。
2. **数据库**：`backups/db/` 最新 `.sql.gz` 恢复（见 §五第 7 步）。
3. **上传文件**：`backend/public/uploads/` 若未纳入备份，迁移时需单独 rsync。
4. 恢复后 `node scripts/build-pages.js` 全量重建静态页。
