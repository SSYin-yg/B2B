# 10 - 生产环境部署手册

## 一、部署架构

```
┌─────────────────┐         ┌─────────────────┐         ┌─────────────────┐
│ GitHub Pages    │◀──push── │ 本项目（本地）    │◀──API── │ Strapi 服务器    │
│ （静态前端）      │         │                 │         │ （PM2 常驻）     │
└─────────────────┘         └─────────────────┘         └─────────────────┘
```

**职责分离**：

| 服务 | 部署位置 | 作用 |
|------|---------|------|
| GitHub Pages | 免费托管 | 静态前端（HTML/CSS/JS） |
| Strapi 服务器 | VPS / 云主机 | Admin + API（询盘接收） |
| 本地电脑 | — | 编辑后台 + build-pages.js 生成 + push 到 GitHub |

## 二、Strapi 服务器部署

### 推荐服务器规格

| 组件 | 最低 | 推荐 |
|------|------|------|
| CPU | 1 vCPU | 2 vCPU |
| 内存 | 1 GB | 2 GB |
| 磁盘 | 20 GB | 40 GB（留 uploads 空间） |
| Node.js | 20 LTS | 20 / 22 LTS |
| 系统 | Ubuntu 22.04 / CentOS 8 | Ubuntu 22.04 LTS |

### 步骤 1：上传代码

```bash
# 方式 A：git clone（推荐）
git clone <repo_url> /opt/strapi-backend
cd /opt/strapi-backend/backend

# 方式 B：scp / rsync 上传
scp -r D:/B2B/backend user@server:/opt/strapi-backend
```

### 步骤 2：安装依赖

```bash
cd /opt/strapi-backend/backend
npm install --omit=dev
```

### 步骤 3：配置 .env

```bash
cp .env.example .env
# 手动编辑 .env，修改以下变量：
# - 所有密钥（generate）
# - SMTP（真实邮箱）
# - CLIENT_URL（改为生产前端地址）
# - SITE_URL（改为真实域名）
# - HOST = 0.0.0.0
```

**必须重新生成所有密钥**，不要复用本地的！

### 步骤 4：构建生产版

```bash
npm run build
```

构建产物在 `backend/build/`，体积约 10-20 MB。

### 步骤 5：PM2 守护进程

```bash
# 安装 PM2
npm install -g pm2

# 创建 ecosystem.config.js（或直接命令启动）
cd /opt/strapi-backend/backend
pm2 start npm --name strapi -- run start
pm2 save            # 保存进程列表
pm2 startup         # 生成 systemd 开机自启命令，执行其输出

# 查看状态
pm2 status
pm2 logs strapi     # 实时日志
pm2 restart strapi
```

### 步骤 6：Nginx 反向代理（可选）

如果要通过 80/443 端口访问，配置 Nginx：

```nginx
server {
  listen 80;
  server_name api.yourdomain.com;

  location / {
    proxy_pass http://127.0.0.1:1337;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

启用 HTTPS：

```bash
sudo certbot --nginx -d api.yourdomain.com
```

### 步骤 7：数据库备份

SQLite 数据库文件在 `backend/.tmp/data.db`，直接复制即可。

**定时备份脚本**：

```bash
#!/bin/bash
# 保存到 /opt/backups/strapi-YYYYMMDD.db
BACKUP_DIR=/opt/backups
mkdir -p $BACKUP_DIR
cp /opt/strapi-backend/backend/.tmp/data.db $BACKUP_DIR/strapi-$(date +%Y%m%d).db
find $BACKUP_DIR -name "strapi-*.db" -mtime +30 -delete  # 保留 30 天
```

加入 crontab：

```cron
# 每天凌晨 2 点备份
0 2 * * * /opt/scripts/backup-strapi.sh
```

**⚠️ 重要**：SQLite 备份必须在 Strapi **停止**或使用 `.backup` 命令时做，否则可能产生损坏副本。最安全做法：

```bash
pm2 stop strapi
cp data.db backup.db
pm2 start strapi
```

或使用 SQLite 自带备份命令：

```bash
sqlite3 .tmp/data.db ".backup /opt/backups/strapi-$(date +%Y%m%d).db"
```

## 三、GitHub Pages 部署

### 本项目已采用的方式

1. 本地运行 `npm run build-pages`
2. 生成的 `equipment/*.html` + `en/equipment/*.html` + `sitemap.xml` + `assets/*.js` 直接在项目根目录
3. `git add` + `git commit` + `git push` 到 GitHub 仓库
4. GitHub Pages 从 main 分支 `/ (root)` 目录自动部署

### 流程示例

```bash
# 本地
cd D:\B2B
git pull                           # 拉取最新
npm run develop                    # 启动 Strapi（后台编辑）
# ... 在后台编辑 Equipment ...
npm run build-pages                # 生成静态页
# 检查输出是否正常
git add .
git commit -m "chore: 更新 crawler-jaw 中文介绍"
git push origin main
```

### 触发 Pages 部署

push 到 GitHub 后，GitHub Pages 自动触发（约 1-2 分钟上线）。通过 `https://ssyin-yg.github.io/B2B/` 访问。

### 域名绑定（可选）

如果有自定义域名（如 `www.minelink-equipment.com`）：

1. GitHub Repo → Settings → Pages → Custom domain → 填写域名
2. DNS 添加 CNAME 记录指向 `<user>.github.io`
3. Pages 页面勾选 **Enforce HTTPS**

**注意**：自定义域名后，`SITE_URL` 必须改为新域名，重新 build-pages，否则 canonical URL 和 sitemap 里还是 GitHub Pages 的地址。

## 四、双环境（开发 vs 生产）

| 项 | 开发 | 生产 |
|----|------|------|
| Strapi URL | `http://localhost:1337` | `https://api.yourdomain.com` |
| 前端静态预览 | `http://localhost:3000`（serve.js） | `https://ssyin-yg.github.io/B2B/` |
| CLIENT_URL | `http://localhost:3000` | `https://ssyin-yg.github.io/B2B` |
| SITE_URL | `https://ssyin-yg.github.io/B2B/` | 同上（或自定义域名） |
| SMTP | 可留空 | **必须配置** |

### 同时维护两份 .env

- 本地 `backend/.env`（开发配置）
- 生产 `backend/.env`（生产配置）

## 五、运维 Checklist

### Strapi 服务器日常

| 频率 | 操作 | 命令 |
|------|------|------|
| 每次修改后 | 备份数据库 | 见上方备份脚本 |
| 每周 | 检查 PM2 状态 | `pm2 status` |
| 每月 | 检查磁盘空间 | `df -h` |
| 每月 | 查看 Strapi 日志 | `pm2 logs strapi --lines 200` |
| 每季度 | 更新 Strapi | `npm run upgrade` |

### 静态部署日常

每次 `npm run build-pages` 后：

1. `git add -A`
2. `git commit -m "update: 描述"`
3. `git push origin main`
4. 等待 GitHub Pages 部署完成
5. 打开 https://ssyin-yg.github.io/B2B/equipment/crawler-jaw.html 抽查 1-2 个页面

### 灾难恢复

| 场景 | 恢复步骤 |
|------|---------|
| Strapi 服务器挂了 | 换机器 → git clone → npm install → 恢复 .env → 恢复 data.db → pm2 start |
| data.db 损坏 | 从最近备份恢复 |
| 前端构建坏了 | `git revert` 或重新 push 上一个好的 commit |
| SMTP 宕了 | 询盘照常入库，SMTP 恢复后新询盘自动发邮件（老的不会补发） |

## 六、CI/CD（可选增强）

GitHub Actions 示例（未实现，供参考）：

```yaml
# .github/workflows/build.yml
name: Build Pages
on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - name: Install deps
        run: npm install
      - name: Start Strapi (CI mode)
        run: cd backend && npm run start &
      - name: Wait + Build
        run: sleep 15 && npm run build-pages
      - name: Deploy to Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: .
```

⚠️ 真正自动化需要 Strapi 在 CI 环境里能启动，SQLite 数据库要有数据。更简单的做法是保持当前手动流程。
