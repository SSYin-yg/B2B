# 07 - 静态页面生成手册

> 📌 **状态（2026-09-07）**：核心内容仍有效，已按当前代码更新 PRUNE 行为与自动化触发链路。
> 权威文档：[17-系统架构文档](./17-系统架构文档.md) §5–6、[18-日常使用手册](./18-日常使用手册.md) §4。

## 一、脚本概述

**核心脚本**：`scripts/build-pages.js`

**作用**：从 Strapi API 拉取 Equipment / Website-image / Site-setting 数据，按 `equipment/_template.html` 模板生成中英文设备详情页、sitemap.xml、equipment-data.js、model-tables.js、website-images.css，并替换静态主站页中的图片/站点名标记。

**关键命令**：

```bash
# 项目根目录执行
npm run build-pages
```

## 二、运行前准备

| 条件 | 检查方法 |
|------|---------|
| Strapi 已启动 | http://127.0.0.1:1337/api/equipments?pagination[pageSize]=1 |
| Equipment 有数据 | `GET /api/equipments` 返回 31 条 |
| Node.js >= 20 | `node -v` |
| equipment/_template.html 存在 | 根目录 `equipment/_template.html` |

## 三、CLI 参数

```bash
node scripts/build-pages.js [options]
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--api-base <URL>` | 指定 Strapi API 地址写入页面 | 空（前端与 API 同源，无需指定） |
| `--no-prune` | 临时关闭过期设备页清理 | **默认开启清理**（2026-09-07 起） |

**示例**：

```bash
# 手动全量重建（后台删除设备后旧页会自动清掉）
node scripts/build-pages.js

# 本次构建不清理过期页面（调试用）
node scripts/build-pages.js --no-prune
```

**过期清理（PRUNE）规则**：构建完成后扫描 `equipment/` 与 `en/equipment/`：

- slug 命中 `data/legacy-equipment-slugs.json`（19 条历史 slug）→ **保留**，由 nginx 301 跳转新页（SEO）；
- 既不在 Strapi、也不在 legacy 映射 → **自动删除**（中英同步，防止已删设备页面残留）。


## 四、输出清单

运行后会在项目根目录生成 / 更新以下文件：

| 输出 | 数量 | 路径 | 说明 |
|------|------|------|------|
| 中文设备详情页 | 31 | `equipment/{slug}.html` | **保持现有 URL 不变** |
| 英文设备详情页 | 31 | `en/equipment/{slug}.html` | 第二阶段新增 |
| sitemap.xml | 1 | `sitemap.xml` | 含所有静态页 + 设备页（中+英） |
| equipment-data.js | 1 | `assets/equipment-data.js` | 从 Strapi 回写（文件头注释标明自动生成） |

**总计生成 62 张设备页面**（31 中文 + 31 英文）。

## 五、模板变量

模板文件：`equipment/_template.html`

模板使用 `{{VAR_NAME}}` 占位符，构建脚本会做严格匹配替换。

| 变量 | 说明 | 示例 |
|------|------|------|
| `{{LANG}}` | html lang 属性 | `zh-CN` / `en` |
| `{{REL}}` | 资源相对路径前缀 | `..`（中文）/ `../..`（英文） |
| `{{SEO_TITLE}}` | `<title>` 和 OG 标题 | 从 `seo_title_zh/en` 读取或回退到名称 |
| `{{SEO_DESCRIPTION}}` | `<meta name="description">` | 从 `seo_description_zh/en` 读取或回退到 desc |
| `{{CANONICAL}}` | canonical URL | 绝对 URL，由 SITE_URL 拼接 |
| `{{HREFLANG_ZH}}` | 中文 hreflang URL | 绝对 URL |
| `{{HREFLANG_EN}}` | 英文 hreflang URL | 绝对 URL |
| `{{OG_TITLE}}` | og:title | 同 SEO_TITLE |
| `{{OG_DESCRIPTION}}` | og:description | 同 SEO_DESCRIPTION |
| `{{OG_LOCALE}}` | og:locale | `zh_CN` / `en_US` |
| `{{OG_IMAGE}}` | og:image | absUrl(og_image || images[0] || 默认封面) |
| `{{PRODUCT_JSONLD}}` | Product schema JSON-LD | escaped 后嵌入 `<script type="application/ld+json">` |
| `{{NAME}}` | 面包屑名称 | 当前语言的设备名称 |
| `{{STATIC_PRODUCT_HTML}}` | 产品区块完整 HTML | 画廊 + 描述 + 特点 + 参数 + 参数表 + 相关设备 |
| `{{PAGE_DATA_JSON}}` | 页面内嵌数据 | 作为 `window.__pageData` 嵌入 |
| `{{API_BASE_SCRIPT}}` | API base 脚本 | 只有传入 `--api-base` 时才有 |
| `{{SLUG}}` | 页面 slug | 用于 `window.MineLinkProductInit(slug)` |

## 六、数据拉取

### Strapi API 端点

```
GET http://localhost:1337/api/equipments?pagination[pageSize]=200&sort=slug:asc
```

**不需要 Authorization**，Public 角色默认有 find 权限。

### 响应结构

```json

      "slug": "wheeled-jaw",

        "desc_zh": "...",
        "desc_en": "...",

        "features_en": [...],
```

## 七、脚本核心逻辑

```
1. 加载 .env 中 STRAPI_URL / SITE_URL
2. 读取 equipment/_template.html
3. fetchEquipment()：GET /api/equipments（另拉 website-images / site-setting）
4. 对每条设备
   ├─ 找到同 category 的最多 3 条相关设备
   ├─ renderPage(entry, related, template, 'zh')  → 写入 equipment/{slug}.html
   └─ renderPage(entry, related, template, 'en')  → 写入 en/equipment/{slug}.html
5. writeSitemap(entries) → sitemap.xml
6. writeDataFiles(entries) → assets/equipment-data.js + model-tables.js
7. 生成 website-images.css + 替换静态主站页标记
8. 过期页面检测与清理（默认开启；legacy 映射页保留，孤儿页删除）
```

## 八、静态页面数据内嵌

每台设备页底部嵌入：

```javascript
window.__pageData = {
  product: {
    id: "crawler-jaw",
    en: "Crawler Jaw Crusher",
    cn: "履带式颚式移动破碎站",
    type: "mobile",
    images: [...],
    desc_zh: "...",
    desc_en: "...",
    features_zh: [...],
    features_en: [...],
    specs: [...]
  },
  modelTables: [...],
  related: [ { id: "slug", en/cn, type, img }, ... ]
};
window.__pageLang = "zh-CN";
window.MineLinkProductInit('crawler-jaw');
```

`product-render.js` 从 `window.__pageData.product` 读取数据渲染页面（画廊切换、参数表、相关设备等），确保：

- 静态页面离线可访问（无需运行时 API 调用）
- 中英文独立页面渲染独立语言版本
- 浏览器端语言切换无需重新拉取 Strapi

## 九、错误处理

| 场景 | 表现 | 解决方案 |
|------|------|---------|
| Strapi 未启动 | 抛出 `获取设备数据失败: HTTP xxx` | 启动 Strapi |
| API 返回空列表 | 抛出 `Strapi 中没有设备数据` | 运行 `npm run migrate` 或后台新增 |
| 单台设备渲染失败 | 跳过该条，记录错误到 failures 数组，最后非零退出 | 查看错误日志，修复该条数据 |
| slug 冲突 | 保留第一台，日志报「slug 重复」 | 后台修改重复 slug |
| 发现孤儿页面 | 自动删除（unknownStale）；legacy 页保留并提示 | 无需处理；确认删除符合预期 |

## 十、自动化（当前已实现，非建议）

| 触发 | 机制 | 日志 |
|------|------|------|
| 后台设备增/改/发布/删除 | lifecycle 钩子 3 秒防抖自动执行本脚本 | `auto-rebuild.log` |
| cron 兜底 | 每 30 分钟比对 API 内容哈希（`.content-hash`），变化才重建 | `auto-rebuild.log` |
| webhook | `POST /rebuild`（nginx 仅放行 127.0.0.1） | `webhook-listener.log` |

本地开发流程：

```bash
# 一个终端
npm run develop          # Strapi

# 另一个终端
npm run serve            # 静态预览 http://localhost:3000

# 编辑后台后（本地无 lifecycle 自动触发时）
npm run build-pages
```

## 十一、重要规则

> ❌ **严禁**手工编辑 `assets/equipment-data.js` 和 `assets/model-tables.js`
> 
> 这两个文件由 `build-pages.js` 从 Strapi 回写，文件头注释已注明"请勿手工编辑"。手工编辑后下一次构建会被覆盖。

> ❌ **严禁**修改设备 URL 结构
> 
> 固定为 `equipment/{slug}.html`（中文）和 `en/equipment/{slug}.html`（英文）。不要变成 `/equipment/{id}`、`/equipment/{slug}/`、`equipment/{slug}.php` 等。
