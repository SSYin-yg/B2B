# 12 - 开发维护手册

## 一、开发环境搭建（完整 checklist）

### 1. 前置

| 组件 | 版本 | 安装方式 |
|------|------|---------|
| Git | 最新 | https://git-scm.com/ |
| Node.js | 20 LTS 或 22 LTS | https://nodejs.org/ |
| npm | >= 6 | 随 Node.js |
| VS Code | — | https://code.visualstudio.com/（推荐） |

### 2. 拉代码

```bash
git clone <repo_url> D:/B2B
cd D:/B2B
```

### 3. 安装依赖

```bash
cd backend
npm install
```

### 4. 配置 .env

```bash
cp .env.example .env
# 编辑 .env — 必须修改密钥为随机值（见 09-环境变量配置说明.md）
```

### 5. 首次启动 Strapi

```bash
npm run develop
# 打开 http://localhost:1337/admin 创建超级管理员
# 创建后 Ctrl+C 停止
```

### 6. 数据迁移

```bash
npm run migrate
# 应该显示 "成功 31 条"（具体看脚本输出）
```

### 7. 静态预览

```bash
# 新开终端
cd D:/B2B
npm run serve
# 打开 http://localhost:3000 验证
```

## 二、日常开发工作流

### 场景 A：编辑设备介绍

```bash
# 1. 启动 Strapi
cd D:/B2B && npm run develop

# 2. 打开后台编辑设备
#    http://localhost:1337/admin

# 3. 发布 + 生成静态
npm run build-pages

# 4. 本地预览
npm run serve
# 浏览器 Ctrl+Shift+R 强制刷新

# 5. Git 提交
git add -A
git commit -m "feat: 更新 crawler-jaw 产品介绍"
git push
```

### 场景 B：新增一台设备

**方法 1（推荐）：后台直接新增**

```bash
npm run develop
# Content Manager → Equipment → Create new entry
# 填写 slug（唯一）、名称、类别等字段
# 保存 → 发布
npm run build-pages
# 自动生成 equipment/{slug}.html + en/equipment/{slug}.html
```

**方法 2：更新 equipment-data.js 并重新迁移**

不推荐，容易覆盖后台编辑内容。

### 场景 C：从 docx 导入设备介绍

```bash
cd backend
# 编辑 scripts/update-equipment-sqlite.js 的 DOCX_MAP 数组
# 添加 { file: 'xxx.docx', slug: 'xxx' }

node scripts/update-equipment-sqlite.js

# 重启 Strapi
npm run develop → Ctrl+C → npm run develop

# 生成静态页
cd .. && npm run build-pages
```

### 场景 D：修改 SEO 配置（canonical / sitemap 域名）

修改项目根目录 `.env` 的 `SITE_URL`：

```bash
# 结尾必须带 /
SITE_URL=https://your-new-domain.com/B2B/
```

然后 `npm run build-pages`。

## 三、新增字段（schema 变更）

### 场景：Equipment 新增 "保修年限" 字段

**步骤**：

1. Admin 后台 → Content-Type Builder → Equipment → Add another field → Text → `warranty_zh` / `warranty_en`
2. 保存。Strapi 会自动更新 `schema.json` 并在 SQLite 加列
3. 重启 Strapi
4. **如果前端要显示这个字段**：
   - 在 `scripts/build-pages.js` 的 `renderPage()` 中加入渲染逻辑
   - 在模板 `equipment/_template.html` 中添加占位符（如果需要）
5. `npm run build-pages` 重新生成

### 场景：新增独立内容类型（很少做）

Strapi Content-Type Builder 可视化创建即可，不建议直接改 schema.json。

## 四、Strapi 升级

```bash
# 1. 备份数据库
cp backend/.tmp/data.db /opt/backups/pre-upgrade.db

# 2. 检查升级路径（dry run）
cd backend
npm run upgrade:dry

# 3. 确认后执行
npm run upgrade

# 4. 启动测试
npm run develop
# 打开后台，功能检查：内容都在吗？Admin 中文正常吗？

# 5. 如果 Admin 翻译构建失败
npm run build-admin-translations
```

⚠️ Strapi v4 → v5 是破坏性升级，**本项目已停留在 v5.52.3**。大版本升级前必须充分测试。

## 五、数据库迁移与导出

### Strapi Transfer（官方工具）

```bash
# 从服务器导出
cd backend
npm run strapi export --file backup --key <encryption-key>
# 生成 backup.tar.gz

# 在新机器导入
npm run strapi import --file backup.tar.gz --key <encryption-key>
```

这会导出完整数据：Equipment + Inquiry + 上传媒体 + 管理员用户 + 角色权限。

### 只导出设备数据

最简单：直接 SQLite

```bash
sqlite3 backend/.tmp/data.db "SELECT * FROM equipments;" > equipments-export.csv
```

### 从旧 equipment-data.js 重新迁移

```bash
cd backend
npm run migrate
# 幂等：有则更新，无则新增
```

## 六、脚本目录说明

```
scripts/                          ← 项目根目录脚本（前端 + 构建）
  build-pages.js                  静态页面生成（核心）
  serve.js                        本地静态服务器（开发预览）

backend/scripts/                   ← 后端维护脚本
  migrate-equipment.js            从 assets/equipment-data.js 迁移 31 台设备
  build-admin-translations.js     预编译 Strapi 官方中文翻译（Admin UI 用）
  update-equipment-sqlite.js      从 docx 文件直接写 SQLite（绕过 API）
  read-docx.js                    docx 文本提取工具
  test-smtp.js                    SMTP 连通性测试（需先 npm install dotenv）
```

### 编写新脚本的约定

1. 放在 `backend/scripts/` 或项目根 `scripts/`
2. 文件头用中文注释说明用途、运行前提和命令
3. 如果操作 SQLite，**必须使用** `better-sqlite3`（已安装），不要调用 Strapi 启动（太重）
4. 如果操作 Strapi API，使用 `fetch()`（Node 20 原生支持）
5. 不要硬编码路径，用 `path.resolve(__dirname, '..')` 方式定位

## 八、代码规范

| 项 | 规范 |
|----|------|
| 语言 | JavaScript（CommonJS `require/module.exports`，Admin 配置用 ESM `import/export`） |
| 异步 | 统一用 `async/await`，不要 callback hell |
| 错误处理 | `try/catch` + 明确的错误日志（`strapi.log.error/warn`） |
| 密钥 | 严禁硬编码，全部走 `.env` + `process.env` |
| 数据库操作 | Strapi 控制器里用 `strapi.documents(uid).create/update()`；脚本里用 `better-sqlite3` |
| 文件路径 | 相对路径 + `path.resolve(__dirname, '../')` 定位根目录 |
| 中文翻译 | Admin UI 中文翻译在 `src/admin/translations/zh-Hans.js`，不直接改 node_modules |
| 敏感字段 | `.env` 必须在 `.gitignore`，提交前检查 |

## 十、Code Review Checklist

修改代码前对照检查：

- [ ] URL 保持 `equipment/{slug}.html` 不变
- [ ] 没有破坏中文/英文 hreflang 互链
- [ ] 没有硬编码密钥/密码/SMTP
- [ ] 没有用 `textContent` 覆盖 `[data-i18n]` 嵌套节点（会丢失子节点）
- [ ] 后端先存库再发邮件的原则没被破坏
- [ ] 数据库写操作有异常处理
- [ ] 错误响应不含敏感信息（堆栈、SMTP 密码等）
- [ ] 文档同步更新（如有 schema 或流程变更）
