## 1. 系统概览

整套系统运行在单台 Linux 服务器上，由 4 个常驻组件 + 2 个定时任务组成：

```
                    互联网访客 / 管理员浏览器
                            │
                            ▼
              ┌─────────────────────────────┐
              │  nginx :80（唯一入口）        │
              │  配置: /etc/nginx/sites-     │
              │  available/minelink          │
              └──┬───────┬──────────┬───────┘
                 │       │          │
    静态页面/资源 │       │          │ /preview/*  → 127.0.0.1:1340
    (location /) │       │          │ /rebuild     → 127.0.0.1:1340（仅本机）
                 │       │          │ 19 条旧 slug 301 跳转
                 │       │          │ sub_filter: {{ORIGIN}} → 访客实际地址（见 §5.5）
                 ▼       ▼
        ┌──────────┐  ┌──────────────────────┐
        │ 磁盘文件  │  │ Strapi 5.52.3 :1337  │
        │/var/www/ │  │ (后台 Admin + REST API)│
        │  B2B     │  │ systemd 用户服务自启   │
        └──────────┘  └─────────┬────────────┘
                                │
                        ┌───────▼────────┐
                        │ PostgreSQL 17  │
                        │ 库: strapi_db  │
                        │ 用户: strapi_user│
                        └────────────────┘

  ┌──────────────────────┐        ┌───────────────────────────┐
  │ webhook-listener      │        │ cron（用户 ssyin）          │
  │ :1340 systemd 服务    │        │ */30min  auto-rebuild.sh   │
  │ b2b-webhook.service   │        │ 周日 03:00 backup-db.sh    │
  │ 草稿预览+重建触发      │        └───────────────────────────┘
  └──────────┬───────────┘
             │ 触发
             ▼
   scripts/build-pages.js（页面构建核心）
   Strapi API → 静态 HTML / sitemap / 数据文件
```

**核心思路**：前端是纯静态文件（nginx 直接吐），所有内容存在 Strapi/PostgreSQL 里；内容变更后由构建脚本重新拉取 API 并生成静态页。编辑与访问彻底解耦，访客侧零动态开销。

## 4. 数据模型（Strapi 内容类型）

### 4.1 equipment（设备，集合类型，含草稿/发布）

字段分组：

- **基本**：`slug`（URL 别名，全站唯一）、`name_cn` / `name_en`、`category`（枚举：mobile 移动破碎站 / crushing 破碎制砂 / screening 筛分输送 / washing 洗砂设备 / parts 易损件）
- **媒体**：`images`（多图）、`og_image`（分享封面）
- **文案**：`desc_zh` / `desc_en`、`features_zh` / `features_en`（组件列表）、`specs`
- **参数表**：`model_tables`（组件）、`model_tables_grid`（equip-editor 可视化编辑的 JSON，构建时优先生成）
- **正文**：`content`（Dynamic Zone：sec.rich-text / sec.image / sec.gallery / sec.list / sec.table / sec.spec-table）
- **SEO**：`seo_title_zh/en`、`seo_description_zh/en`
- **关联**：`related_equipments`（手工指定相关设备；为空时构建按同分类自动补 3 台）
- **UI 微调**：`ui_section_*`（json，控制详情页各分节的显隐/标题等）

### 4.2 其余内容类型

| 类型 | 用途 | 关键字段 |
|------|------|---------|

| website-image | 网站图片槽位 | key（槽位标识）、page/position/category、image、alt、enabled、sort_order |

注册 3 个自定义字段（型号参数表可视化网格编辑、普通表格、编辑页分节标题），并向设备编辑页右侧注入「**打开草稿预览**」按钮（新标签页打开 `/preview/`）。

## 5. 页面构建管线（scripts/build-pages.js）

**输入**（全部走 Strapi 公开 API，无需鉴权）：
`/api/equipments`（200 条，含全部 populate）、`/api/website-images`、`/api/site-setting`。

**输出**：

| 产物 | 说明 |
|------|------|
| `equipment/{slug}.html` + `en/equipment/{slug}.html` | 每台已发布设备中英各一页，模板 `equipment/_template.html` |
| `sitemap.xml` | 静态页 7 + 中文设备 N + 英文设备 N，域名用 `{{ORIGIN}}` 占位符（见 §5.5） |
| `assets/equipment-data.js` / `model-tables.js` | 数据回写（首页/目录页客户端渲染用） |
| `assets/website-images.css` | 图片槽位样式 |
| 6 个静态主站页 | 替换 `data-wb-img` 图片标记与站点名等占位符 |

**过期清理（PRUNE，默认开启）**：构建完成后扫描 `equipment/` 与 `en/equipment/`，磁盘上有、但 Strapi 已不存在的页面分两类：

- **known legacy**：slug 命中 `data/legacy-equipment-slugs.json`（19 条）→ **保留**（nginx 对其做 301 到新 slug，保 SEO）；
- **unknown stale**：真正的孤儿页（如已删除的设备）→ **自动删除**（中英同步）。

`--no-prune` 参数可临时关闭清理；slug 冲突时保留第一台并在日志中报错。

**CLI 参数**：`--api-base <url>`（API 前缀，写入页面的 MINELINK_API_BASE）、`--no-prune`。

## 5.5 站点地址机制：{{ORIGIN}} 动态替换（2026-09 上线）

**解决的问题**：本站部署在个人服务器上，访客使用的 IP 与端口随时会变（动态 IP / 换端口 / 换域名 / DDNS）。若把绝对地址写死进静态页，每次地址变化都要重新构建，忘改就出现旧地址死链。

**机制**：构建期与运行期分工，站点地址永远不落盘。

```
构建期（build-pages.js）
  backend/.env 的 SITE_URL = 留空
  → SITE_URL 回退为占位符 '{{ORIGIN}}'（build-pages.js:89）
  → 静态页 canonical / og:url、sitemap.xml 的 <loc> 全部写成 {{ORIGIN}}/...
  → 换地址 = 无需重新构建

运行期（nginx，/etc/nginx/sites-enabled/minelink 第 9-11 行）
  sub_filter '{{ORIGIN}}' '$scheme://$http_host';
  sub_filter_types text/xml application/xml;   # text/html 默认始终处理
  → 响应发出时把占位符替换为访客实际访问的 协议://主机[:端口]
  → 用任何 IP / 端口 / 域名访问，页面里的地址都自动与之一致
```

**生效范围**：

| 位置 | 构建产物中的形态 | 访客看到 |
|------|-----------------|---------|
| 静态页 `<link rel="canonical">` / `og:url` | `{{ORIGIN}}/equipment/xxx.html` | `http://当前地址/equipment/xxx.html` |
| `sitemap.xml` 的 `<loc>` | `{{ORIGIN}}/...` | 同上 |
| 前端 JS（询盘表单、渲染脚本） | 同源相对/根相对路径 | 天然与地址无关，无替换需要 |
| Strapi 预览按钮 URL | 不落盘，`backend/config/admin.js` 运行时取请求 Host | 动态，无需配置 |

**边界与注意**：

1. 替换只发生在 **nginx 出站响应**上。绕过 nginx 直接读磁盘文件（`cat sitemap.xml`）看到的是 `{{ORIGIN}}` 字面量，属正常现象，不是故障。
2. 该机制要求 `.env` 的 `SITE_URL` **保持留空**。一旦设置了真实地址（例如误运行 `scripts/update-site-url.sh`），构建产物就会写死该地址，动态机制失效——恢复方法见 18 号手册 §6。
3. `sub_filter` 对已 gzip 压缩的响应无效；当前 nginx 的 `gzip_types` 仅默认 text/html 且 sub_filter 在 gzip 之前执行，sitemap.xml（text/xml）不受影响。
4. `{{ORIGIN}}` 替换跟随的是请求的 Host 头；爬虫抓取时拿到什么地址就写入什么地址，对 SEO 无副作用（canonical 恒等于访客实际访问地址）。

**验证方法**（无需等真实 IP 变化，本机模拟）：

```bash
curl -s -H "Host: 203.0.113.7:9999" http://127.0.0.1/sitemap.xml | grep -m2 '<loc>'
# 应输出 http://203.0.113.7:9999/... ；残留 {{ORIGIN}} 计数应为 0
```

## 6. 重建触发链路（三路汇合到 build-pages.js）

| # | 触发源 | 机制 | 日志 |
|---|--------|------|------|
| 1 | **lifecycle 钩子**（主链路） | 设备 afterCreate/afterUpdate/afterDelete → 3 秒防抖 → `node build-pages.js`（`backend/src/api/equipment/content-types/equipment/lifecycles.js`，ROOT 按 `__dirname` 向上 6 级解析） | `auto-rebuild.log` |
| 2 | **cron 兜底** | 每 30 分钟 `auto-rebuild.sh` 拉取 API 求 md5，与 `.content-hash` 不同才重建（注意：「创建后又删除」净效果为无变化，哈希不变不会触发） | `auto-rebuild.log` |
| 3 | **webhook /rebuild** | `POST /rebuild`（nginx 限制 `allow 127.0.0.1`）→ 3 秒防抖重建 | `webhook-listener.log` |

手动执行：`node scripts/build-pages.js`。

> 历史 bug 备忘：lifecycle 的 ROOT 曾少算一级导致自动重建从未成功（已于 2026-09-07 修复）；PRUNE 曾默认关闭导致删除设备后前端残留（同日改为默认开启）。

## 7. 草稿预览链路

两种入口，同一渲染服务（webhook-listener `handlePreview`）：

1. **Strapi 原生预览**（后台右上角 Preview，iframe 内嵌）：
   `backend/config/admin.js` 的 handler 生成 URL —— 已发布 → 静态页地址；**草稿 → `/preview/{slug}.html?doc=<documentId>`**（英文 `/preview/en/...`）。
   iframe 首次加载无凭证 → webhook-listener 返回**引导页**，页面 JS 从 `localStorage.jwtToken` 读取管理员 JWT 后自动带 `&token=` 重载；无凭证则 302 回已发布静态页。
2. **equip-editor 插件按钮**「打开草稿预览」：新标签页直接带 token 打开 `/preview/`。

**渲染**：webhook-listener 用浏览器带来的 JWT 调 Strapi `content-manager` 接口取 `status=draft` 数据，用与静态页**完全相同**的模板渲染（不写盘），注入「草稿」横幅与 `noindex`。

**安全要点**：

- 后台页面 CSP `frame-src` 由 `backend/config/middlewares.js` 配置为 `'self'` + `admin.preview.allowedOrigins`（localhost:3000 开发用）——`'self'` 保证任意 IP/端口访问时 iframe 不被屏蔽（2026-09-07 修复，此前只有 localhost 白名单导致「该内容被屏蔽了」）；
- 预览 JWT 约 30 分钟过期 → 预览页显示「登录已过期」，回后台重新登录即可；
- 无有效 JWT 时预览接口不会泄漏任何草稿内容。

## 8. 询盘与邮件链路

```
访客填写 #leadForm（各页面底部）
  → assets/inquiry-form.js 前端校验
  → POST /api/inquiry（public 权限）
     ├─ Inquiry 入库（submitted_at、来源设备）
     ├─ nodemailer → SMTP（.env: SMTP_HOST/PORT/USER/PASS）
     │    收件人 SALES_EMAIL；未配置 SMTP 则跳过发信仅入库（日志 warn）
     └─ maillog 记录每次发信结果（成功/失败+错误信息）
  → 回写 Inquiry.email_sent / mail_status
```

**重发**：`POST /api/inquiry/resend`，请求头 `x-retry-key: <backend/.env 的 RETRY_KEY>`，body `{"documentId":"..."}`。对已存在询盘重新发信，**不新建记录**，同样写 maillog。该接口对 public 开放，仅靠 RETRY_KEY（32 位随机）防护，勿泄露。

## 11. 备份与恢复

- **自动**：cron 周日 03:00 `backup-db.sh` → `pg_dump | gzip` → `backups/db/strapi_db-<时间戳>.sql.gz`（权限 600，保留 56 天，日志 `backups/db.log`）。
- **恢复**：`gunzip -c backups/db/xxx.sql.gz | PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db`，随后 `node scripts/build-pages.js` 重建静态页。
- **代码**：git 仓库（remote: github.com/SSYin-yg/B2B，私有）。

## 12. 环境与配置

- 全部运行时配置在 `backend/.env`（模板见 `backend/.env.example`）：密钥类（APP_KEYS/ADMIN_JWT_SECRET/...）、数据库（PostgreSQL）、SMTP + SALES_EMAIL + RETRY_KEY、SITE_URL / CLIENT_URL（**两者均保持留空**，配合 `{{ORIGIN}}` 动态地址机制，见 §5.5）。
- **IP/端口变更**：默认**无需任何操作**——站点地址由 nginx `sub_filter` 运行期动态替换。仅端口变化时需同步修改 nginx `listen` 并 reload。操作细节与验证清单见 18 号手册 §6。
