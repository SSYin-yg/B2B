# 01 - 项目架构说明

## 一、整体架构

本项目是 **Strapi + 纯静态前端** 的混合架构，核心设计原则：

1. **前端保持静态 HTML 部署**（GitHub Pages，无需 Node 运行时）
2. **内容编辑在 Strapi Admin**（可视化后台）
3. **静态页面由 `build-pages.js` 从 Strapi API 拉取数据生成**
4. **询盘表单 POST 到 Strapi 自定义路由 `/api/inquiry`**
5. **中英文使用独立 URL**（`/equipment/{slug}.html` vs `/en/equipment/{slug}.html`）

## 三、Strapi 内容类型

### Equipment（设备）— 31 条

| 字段 | 类型 | 说明 |
|------|------|------|
| slug | string（unique, required） | URL 标识，对应 `equipment/{slug}.html` |
| name_cn | string（required） | 中文名称 |
| name_en | string（required） | 英文名称 |
| category | enumeration（required） | mobile / crushing / screening / washing / parts |
| images | json | 图片路径数组（中文页相对 `assets/images/equipment/`） |
| desc_zh | text | 中文产品介绍 |
| desc_en | text | 英文产品介绍 |
| features_zh | json | 中文特点列表（数组） |
| features_en | json | 英文特点列表（数组） |
| specs | json | 规格参数（数组，每项含 k_zh/k_en/v） |
| model_tables | json | 型号参数表（多表） |
| seo_title_zh / seo_title_en | string | SEO 标题 |
| seo_description_zh / seo_description_en | text | SEO 描述 |
| og_image | string | 社交分享图 URL（为空时 build-pages 用网站默认） |

启用 Draft & Publish（草稿发布）。

## 五、静态生成原理

1. `scripts/build-pages.js` 读取 `equipment/_template.html` 模板
2. 从 `http://localhost:1337/api/equipments?pagination[pageSize]=200` 拉取所有设备
3. 对每台设备执行两次 `renderPage(entry, related, template, 'zh'|'en')`
4. 模板变量包括：`{{LANG}}` `{{REL}}` `{{SEO_TITLE}}` `{{SEO_DESCRIPTION}}` `{{CANONICAL}}` `{{HREFLANG_ZH}}` `{{HREFLANG_EN}}` `{{OG_TITLE}}` `{{OG_DESCRIPTION}}` `{{OG_LOCALE}}` `{{OG_IMAGE}}` `{{PRODUCT_JSONLD}}` `{{NAME}}` `{{STATIC_PRODUCT_HTML}}` `{{PAGE_DATA_JSON}}` `{{API_BASE_SCRIPT}}` `{{SLUG}}`
5. 输出到 `equipment/{slug}.html` 和 `en/equipment/{slug}.html`
6. 同步生成 `sitemap.xml`、回写 `assets/equipment-data.js` 和 `assets/model-tables.js`

## 六、设备详情页数据源

设备详情页 `equipment/{slug}.html` 是 **完全静态页面**，不依赖浏览器运行时拉取 Strapi API。页面内嵌：

```javascript
window.__pageData = { product: {...}, modelTables: [...], related: [...] };
window.__pageLang = 'zh-CN';
```

`assets/product-render.js` 从 `window.__pageData` 读取数据渲染页面（画廊、特点、参数表、相关设备），确保页面离线可访问。

## 七、前端语言切换机制

| 场景 | 机制 | 文件 |
|------|------|------|
| 首页/目录/FAQ 等共享页 | `applyLang(lang)` 替换所有 `[data-i18n]` 节点文本 | `assets/i18n.js` |
| 设备详情页 | `product-render.js` 拦截按钮点击 → `location.href` 跳到另一语言 URL | `assets/product-render.js` |
| 初始化 | `detectLangByIP()` 检测 URL `/en/` 或 `localStorage.minelink-lang` 或 IP 地理 | `assets/i18n.js` |

## 八、询盘流程

```
浏览器表单 → POST /api/inquiry → Strapi inquiry.submit() 控制器
  ├─ 后端校验（customer_name / email∪whatsapp / country / message / equipment）
  ├─ 先存库 → strapi.documents('api::inquiry.inquiry').create()
  ├─ 再发邮件 → nodemailer → sales@minelink.cn
  │   （SMTP 未配置时仅 warn，不影响入库）
  └─ 返回 { submitted: true, emailSent: boolean, documentId }
```

## 九、数据库

- 类型：SQLite（better-sqlite3）
- 路径：`backend/.tmp/data.db`
- 表：`equipments` / `inquiries` / Strapi 系统表（`strapi_users`, `strapi_roles`, `strapi_permissions`, `strapi_core_store_settings`, `strapi_transfer_tokens`, `strapi_api_tokens` 等）
- 迁移：首次由 Strapi 自动创建；表结构变更需手动 `CREATE TABLE` 或 Strapi Content-Type Builder

## 十、Admin UI 定制

- 默认语言：**简体中文**（`src/admin/app.js` 中 `defaultLocale: 'zh-Hans'`）
- 翻译包：由 `scripts/build-admin-translations.js` 从 `@strapi/admin` 及各插件的 `.mjs` 中预编译合并到 `src/admin/translations/zh-Hans.js`
- **Admin UI 的 locale 与 Strapi Content 的 i18n locale 完全独立**，互不影响
