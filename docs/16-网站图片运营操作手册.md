# 16. 网站图片运营操作手册

> 面向运营人员：如何在 Strapi 后台查看、搜索、更换、上传网站公共图片，以及更换后如何重新生成网站。
> 适用功能：网站图片管理（首页 Banner、页头背景、Logo、分享图、Favicon 等）。设备产品图片不在此范围内，仍在 Equipment 中管理。

---

## 一、进入网站图片

1. 打开 Strapi 后台（默认 `http://<服务器>/admin`）。
2. 左侧菜单 **内容（Content） → 网站图片**。
3. 进入后可以看到网站所有可管理的图片清单。

列表展示列：缩略图、图片名称、所属页面、使用位置、图片分类、启用、排序。

---

## 二、查看与搜索

- **搜索**：列表右上角搜索框，输入图片名称（如「首页 Banner」）即可过滤。
- **按页面筛选**：点击「所属页面」列头筛选（首页 / 行业方案 / 服务支持 / 关于我们 / 常见问题 / 设备目录 / 全局）。
- **按位置筛选**：点击「使用位置」列头（顶部 Banner / 页头背景 / 侧边栏 / Header / 页脚 / 社交分享图 / 网站图标）。
- **按分类筛选**：点击「图片分类」列头。
- **按启用状态筛选**：点击「启用」列头（已启用 / 已禁用）。
- **排序**：点击「排序」列头按 `sort_order` 排序。

---

## 三、查看使用位置

每个图片条目的 **使用位置** 字段，以及编辑页的 **用途说明** 字段，都写明了这张图片用在网站哪里、建议尺寸。例如：

- 「首页 Banner 1」→ 首页顶部轮播第 1 张，建议 1920×900 横图。
- 「行业方案页头背景」→ 行业方案页顶部深色页头背景，建议 1920×600 横图。

如果不确定某张图用在哪，看 **图片名称** + **使用位置** + **用途说明** 三栏即可。

---

## 四、更换图片（核心操作）

1. 在列表中找到要更换的图片（如「首页 Banner 1」），点击进入**编辑页**。
2. 在「图片」一栏点击当前图片，打开 **媒体库（Media Library）**。
3. 选择一张已有图片，或点击「上传」选择本地新图片（支持 JPG / PNG / WebP / SVG）。
4. 保存。
5. 到服务器运行重新生成命令（见第八节），网站对应位置即更新。

> 您**不需要**填写或修改任何图片 URL、HTML、CSS。更换图片后，旧图片仍保留在媒体库中，不会被删除。

---

## 五、上传新图片

- 在「图片」选择框中点击 **上传（Upload）**，选择本地文件。
- 也可在 Strapi 顶部 **媒体库** 中先批量上传，再回来选择。
- 建议尺寸参考各条目的「用途说明」；过大图片会拖慢加载，建议单图不超过 500KB（WebP 优先）。

---

## 六、修改 ALT（替代文字）

编辑页 **替代文字 ALT** 字段：
- 用于图片无法显示时、屏幕阅读器与搜索引擎的可访问性 / SEO。
- 建议用英文简要描述图片内容，例如 `Mining equipment working at a construction site`。
- 填写后重新生成，网站对应 `<img>` 或 OG 的 alt 会更新。

---

## 七、修改图片说明 / 启用禁用 / 排序

- **图片说明**：可留空的备注（如「矿山破碎生产线现场」），仅后台可见。
- **启用 / 禁用**：关闭后该位置不使用这张图片，页面保持原有外观（不会出现裂图）。确认图片正确后再关闭。
- **排序**：同一位置内多张图片的显示顺序，数字越小越靠前（如首页三张 Banner 用 10 / 20 / 30）。

> **标识 key** 字段禁止修改——它是系统定位图片的编号，改了网站对应位置将取不到图。

---

## 八、更换后重新生成网站

保存图片后，必须重新生成静态页面，新图片才会写入网站：

```bash
cd /var/www/B2B
node scripts/build-pages.js
```

或在项目目录运行 `npm run build-pages`。

生成成功后：
- 首页 Banner、OG 分享图等对应位置自动更新。
- 控制台会打印每个页面的处理结果（如 `· index.html — 替换 3 处标记: home_hero_1, home_hero_2, home_hero_3`）。

> 若 Strapi 已配置 webhook 自动重建，部分修改可能已自动生成，再次手动运行一遍以确保最新。

---

## 九、预览与确认

重新生成后，直接刷新网站对应页面即可看到新图片。建议：
- 用浏览器无痕窗口打开，避免缓存。
- 检查桌面端与手机端（响应式）显示是否正常。
- 右键图片「检查」确认 `src` / `background-image` 指向 `/uploads/...` 或 `assets/images/equipment/...`（不再是旧图）。

---

## 十、恢复图片（误换回退）

- **更换错图片**：回到该条目编辑页，重新选择正确图片并保存，再重新生成。旧图仍在媒体库。
- **想回到网站原始图片**：当前版本「禁用」该槽位并不能回退到原始图（页面保持上次生成的图）。如需完全回退到初始状态，请联系开发人员在 Strapi 后台清空该条目的图片并重新生成，或恢复备份 `backups/pre-website-image-*.tar.gz` 中的对应静态页。
- **误删媒体库图片**：删除前系统会提示该图片是否被网站图片配置引用；仍被引用的图片禁止删除。

---

## 十一、避免误删

- 运营「更换图片」不会删除旧图片，旧图保留在媒体库。
- 只有明确删除媒体库文件时才会删除；删除前请确认该图片未被任何「网站图片」条目引用。
- 不要删除 `assets/images/equipment/` 目录下的文件，除非开发人员确认其已无任何引用。

---

## 十二、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 更换后页面没变 | 未重新运行 `build-pages.js` | 保存后运行生成命令（第八节） |
| 图片显示裂图 | 该槽位禁用或图片未配置 | 在后台为该槽位配置图片并启用，重新生成 |
| 列表看不到某张图 | 被搜索 / 筛选条件隐藏 | 清除筛选条件，或用名称搜索 |
| ALT 没生效 | 该图片是背景图模式 | 背景图模式的 ALT 仅影响 OG / 无障碍，普通 `<img>` 会生效 |
| 想加新位置（如新 Banner） | 需开发在 `scripts/website-image-slots.js` 增加槽位 | 联系开发人员，不要手动改 HTML |

## 13. 换图 → 前端生效 — 完整操作

> 本章是日常运营最常用的流程。

### 13.1 后台改图（3 步）

1. 进入 Strapi Admin → 内容 → 网站图片。
2. 点击要改的图，例如「**首页 Banner 1**」（`key=home_hero_1`）。
3. 点击「图片」字段右上的 "+" → 上传或从 Media Library 选择新图 → 关闭弹窗 → 保存。

### 13.2 前台生效（2 步）

#### 方式 A：通知开发人员重建

要求开发在服务器跑：

```bash
cd /var/www/B2B
node scripts/build-pages.js
```

#### 方式 B：联系运维触发 webhook

如果 Strapi webhook 已配置（默认是开发的时候改 Equipment 自动 rebuild），网站图片改了不会自动 rebuild——需要：

- 方式 B1：联系运维手动跑 build-pages
- 方式 B2：联系开发把 website-image 也加入 webhook 监听 → **改完图几秒后自动 rebuild**

> 第二种方式更省事，一次配置长期受益。

### 13.3 浏览器验证

打开首页，看对应位置是否变成新图。
验证点：
- 缩略图是否变化
- 文字位置是否变（如配图更换为不同尺寸，仍能套用)
- 移动端是否同样更换

### 13.4 异常处理

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| 改了图但前台无变化 | build-pages.js 没跑 | 联系运维跑 `node scripts/build-pages.js` |
| 图片变成 404 | Media Library 中被删了 | 在后台重新上传 |
| 首页乱版 | 用了非 16:9 的图 | 建议尺寸 1300×900 以上 |
| 多个图位置错位 | 配图比例不对 | 缩放到建议尺寸再上传 |
| 想换 Logo 但没反应 | `site_logo` 仍 disabled | 这是预期；上传 Logo 并将 enabled=true |

### 13.5 不同位置的最佳尺寸

| 位置 | 建议尺寸 | 比例 |
| ---- | -------- | ---- |
| 首页 Hero 1/2/3 | 1920×900 | 16:9 |
| 首页行业方案配图 | 1300×900 | 4:3 |
| 关于我们侧栏 | 800×900 | 8:9 竖图 |
| 行业方案/服务支持/FAQ/设备目录页头 | 1920×600 | 32:10 横幅 |
| 默认 OG 分享图 | 1200×630 | 1.91:1 |
| Logo | 300×100 | 3:1 |
| Favicon | 32×32 / 64×64 | 1:1 |

### 13.6 注意事项

1. **不要修改 key**：key 是系统唯一标识，运营看不到也要视作只读。
2. **不要手动改 HTML/CSS**：下次 build 会被覆盖。
3. **不要删 assets/images/ 下原图**：下次 build 会被重新登记到 Strapi 媒体库。
4. **每改一张图都建议**：保存后通知开发 rebuild——避免后续累积。

### 13.7 想看自己改的图片在哪生效？

- 已启用槽位（即 enabled=true 的 11 项）改了 → 会真正影响前端
- 未启用槽位（site_logo、favicon）改了 → 在数据库，但前台无变化（合理设计）

如需启用 site_logo / favicon：在后台挑图上传后，将 enabled 设为 true，再通知开发 rebuild 即可。
