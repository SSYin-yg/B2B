# 11 - 故障排查手册

> 📌 **状态（2026-09-08）**：已更新至当前部署（nginx + PostgreSQL；Strapi 为 systemd 用户服务 `strapi-b2b`，开机自启）。
> 快速速查表见 [18-日常使用手册 §8](./18-日常使用手册.md)。日志位置：`journalctl --user -u strapi-b2b`（Strapi）、`auto-rebuild.log`（自动重建）、`webhook-listener.log`（预览/重建服务）。

## 一、Strapi 启动失败

### 现象

后台/首页 502，或 `systemctl --user status strapi-b2b` 显示 failed。

### 排查步骤

```bash
# 1. 看错误日志
journalctl --user -u strapi-b2b -n 50 --no-pager

# 2. 确认 Node.js 版本
node -v  # 要求 >= 20

# 3. 确认依赖完整
cd backend && npm install

# 4. 检查 .env 是否被意外删除或密钥格式错误
grep -c "=" backend/.env
# APP_KEYS 需要逗号分隔的多个 key，不要写成单行

# 5. 检查 PostgreSQL 可连
systemctl status postgresql
PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db -c "SELECT 1;"

# 6. 端口冲突（1337 被占用）
ss -tlnp | grep 1337
kill <pid>

# 7. 重启
systemctl --user restart strapi-b2b
```

## 二、Admin 后台打不开

### 现象

浏览器访问 `http://localhost:1337/admin` 显示白屏或连接拒绝。

### 排查

| 现象 | 原因 | 解决 |
|------|------|------|
| Chrome: ERR_CONNECTION_REFUSED | Strapi 没启动 | `npm run develop` |
| 白屏 + 控制台报错 "Cannot find module" | Admin 翻译未构建 | `cd backend && npm run build-admin-translations` 然后重启 |
| 中文显示英文 + 部分缺失 | Admin UI locale 配置问题 | 检查 `src/admin/app.js` 中 `defaultLocale: 'zh-Hans'` |
| 一直 Loading | 浏览器缓存 | `Ctrl+Shift+R` 硬刷新 |

## 三、API 返回 403 Forbidden

### 场景

- POST `/api/inquiry` 返回 403
- GET `/api/equipments` 返回 403（不应该）

### 排查

1. **Public 角色权限**：Settings → Roles → Public → 检查：
   - Inquiry: create ✅
   - Equipment: find ✅
2. **API Token**：如果 API 需要认证，在请求头加 `Authorization: Bearer <token>`
3. **CORS**：前端 URL 不在 `config/server.js` 的 cors.origin 白名单里 → 加进去 + 重启

```bash
# 快速测试权限
curl http://localhost:1337/api/equipments
# 返回 200 JSON → Public 有 find 权限 ✅
```

## 四、询盘不入库

### 排查链

```
浏览器 → 表单提交
  ↓ 前端成功了吗？
  │ ├─ 页面显示 "提交中..."？ → 网络问题，Strapi 没启动
  │ ├─ 显示 "成功" → 看后端日志
  │ └─ 显示 "失败" → 403 权限 / 500 SQL 错误
  ↓ Strapi 日志
  ├─ [inquiry] 数据库写入失败
  │   └─ 检查 inquiries 表结构（Strapi CLI 重建）
  └─ POST /api/inquiry → 200
      └─ 入库成功了，刷新 Admin Inquiry 列表
```

### 检查表是否存在（PostgreSQL）

```bash
PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db -c "\dt" | grep inquiries
# 无输出 → inquiries 表不存在 → 检查内容类型定义后在后台 Content-Type Builder 确认
```

## 六、build-pages.js 失败

### 常见错误

| 错误信息 | 原因 | 解决 |
|---------|------|------|
| `获取设备数据失败: HTTP xxx` | Strapi 没启动或地址错 | 启动 Strapi，检查 STRAPI_URL |
| `Strapi 中没有设备数据` | 数据库空 | `npm run migrate` |
| `ENOENT: no such file or directory` | 模板文件缺失 | 确认 `equipment/_template.html` 存在 |
| `[slug] 渲染失败: ...` | 单条设备数据格式错误 | 后台编辑该设备，修复 JSON 字段 |

### 清理过期页面

```bash
# 2026-09-07 起清理默认开启，直接重建即可
node scripts/build-pages.js
# 需要临时不清理（调试）时：
node scripts/build-pages.js --no-prune
```

## 七、前端设备页显示异常

### 场景

| 现象 | 排查 |
|------|------|
| 所有设备页 404 | `build-pages.js` 没跑，或 `equipment/` 目录被清空 |
| 某一台 404 | slug 被删了但文件还在，或 slug 改了没重新 build |
| 页面有标题但没内容 | `window.__pageData.product` 为空 → 后台该条数据的 images/specs 字段格式错 |
| 画廊不显示 | images 字段是字符串而非数组 → 后台修复 JSON |
| 语言切换不生效 | 浏览器缓存旧的 `product-render.js` → `Ctrl+Shift+R` |

### 本地验证

```bash
# 1. 启动静态服务器
npm run serve

# 2. 打开
# http://localhost:3000/equipment/crawler-jaw.html
# http://localhost:3000/en/equipment/crawler-jaw.html
```

## 八、后台预览异常

### 预览 iframe 显示「该内容被屏蔽了」

CSP `frame-src` 缺 `'self'`。检查 `backend/config/middlewares.js` 的 strapi::security 配置包含 `'frame-src': ["'self'"]`，修改后重启 Strapi。（2026-09-07 已修复，正常不应再出现。）

### 预览显示「登录已过期」

后台 JWT 约 30 分钟有效期 → 回后台刷新/重新登录后再点预览。

### 点击预览后 404

- 草稿未保存或设备缺 slug → 先在后台填写 slug 并保存；
- webhook-listener 未运行 → `systemctl status b2b-webhook`，异常则 `sudo systemctl restart b2b-webhook`。

## 九、设备页语言切换问题

### 现象：第一次切英文失败，第二次才成功

这个问题已修复，详见 [本次会话记录] 和 `assets/i18n.js`、`assets/product-render.js` 的 git log。

### 现象：语言切换后部分文本没更新

可能是页面内嵌了 i18n.js 执行前就渲染好的内容。检查：

1. `assets/i18n.js` 引用是否有 `defer`（应该有，确保 DOMContentLoaded 后执行）
2. `product-render.js` 是否正确监听了 `minelink:lang` 事件

## 十、PostgreSQL 数据库异常

### 检测连接与表

```bash
systemctl status postgresql
PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db -c "\dt"
PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db -c "SELECT count(*) FROM equipments;"
```

### 恢复（用最近备份）

```bash
# 1. 停止 Strapi
systemctl --user stop strapi-b2b

# 2. 用最近的备份恢复
gunzip -c /var/www/B2B/backups/db/strapi_db-YYYYMMDD-HHMMSS.sql.gz | \
  PGPASSWORD=<密码> psql -h 127.0.0.1 -U strapi_user -d strapi_db

# 3. 重启 Strapi + 重建静态页
systemctl --user start strapi-b2b
node scripts/build-pages.js
```

### 彻底重建（兜底，数据丢失）

删除重建空库后，后台手工录入设备，或 `npm run migrate`（从 assets/equipment-data.js 导入）。

## 十一、性能问题

| 现象 | 排查 |
|------|------|
| Strapi develop 模式慢（正常） | develop 模式热更新开销大，生产用 start |

## 十二、自动重建不生效

| 现象 | 原因 | 解决 |
|------|------|------|
| 后台改了内容前台没变 | lifecycle 触发失败 | `tail auto-rebuild.log` 看「重建失败」行；确认 `backend/src/api/equipment/content-types/equipment/lifecycles.js` 路径解析正确（2026-09-07 已修复） |
| 创建又删除后没动静 | cron 哈希净变化为零，属正常 | 手动 `node scripts/build-pages.js` |
| 已删设备页面还在 | 构建时 PRUNE 被关闭 | 确认没有传 `--no-prune`，重新构建 |
