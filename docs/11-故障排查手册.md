# 11 - 故障排查手册

## 一、Strapi 启动失败

### 现象

`npm run develop` 直接报错退出或反复重启。

### 排查步骤

```bash
# 1. 看错误日志（Strapi 会打印详细错误）
npm run develop

# 2. 确认 Node.js 版本
node -v  # 要求 >= 20

# 3. 确认依赖完整
cd backend && npm install

# 4. 检查 .env 是否被意外删除或密钥格式错误
cat backend/.env
# APP_KEYS 需要逗号分隔的多个 key，不要写成单行

# 5. 检查 SQLite 数据库
ls -la backend/.tmp/data.db
# 如果文件损坏，删除后 Strapi 会自动重建（但数据会丢失！先备份）

# 6. 端口冲突
# 1337 被占用时修改 .env 中 PORT 或结束占用进程
netstat -ano | findstr :1337
taskkill /PID <pid> /F

# 7. 清理后重试
cd backend && rm -rf .tmp && npm run develop
```

## 二、Admin 后台打不开

### 现象

浏览器访问 `http://localhost:1337/admin` 显示白屏或连接拒绝。

### 排查

| 现象 | 原因 | 解决 |
|------|------|------|
| Chrome: ERR_CONNECTION_REFUSED | Strapi 没启动 | `npm run develop` |
| 白屏 + 控制台报错 "Cannot find module" | Admin 翻译未构建 | `cd backend && npm run build-admin-translations` 然后重启 |
| 中文显示英文 + 部分缺失 | Admin UI locale 配置问题 | 检查 `src/admin/app.js` 中 `defaultLocale: 'zh-Hans'` |
| 一直 Loading | 浏览器缓存 | `Ctrl+Shift+R` 硬刷新 |

## 三、API 返回 403 Forbidden

### 场景

- POST `/api/inquiry` 返回 403
- GET `/api/equipments` 返回 403（不应该）

### 排查

1. **Public 角色权限**：Settings → Roles → Public → 检查：
   - Inquiry: create ✅
   - Equipment: find ✅
2. **API Token**：如果 API 需要认证，在请求头加 `Authorization: Bearer <token>`
3. **CORS**：前端 URL 不在 `config/server.js` 的 cors.origin 白名单里 → 加进去 + 重启

```bash
# 快速测试权限
curl http://localhost:1337/api/equipments
# 返回 200 JSON → Public 有 find 权限 ✅
```

## 四、询盘不入库

### 排查链

```
浏览器 → 表单提交
  ↓ 前端成功了吗？
  │ ├─ 页面显示 "提交中..."？ → 网络问题，Strapi 没启动
  │ ├─ 显示 "成功" → 看后端日志
  │ └─ 显示 "失败" → 403 权限 / 500 SQL 错误
  ↓ Strapi 日志
  ├─ [inquiry] 数据库写入失败
  │   └─ 检查 inquiries 表结构（Strapi CLI 重建）
  └─ POST /api/inquiry → 200
      └─ 入库成功了，刷新 Admin Inquiry 列表
```

### SQL 检查表是否存在

```bash
node -e "const Database=require('better-sqlite3');const db=new Database('backend/.tmp/data.db');console.log(db.prepare(\"SELECT name FROM sqlite_master WHERE name='inquiries'\").all());db.close();"
# 如果无输出 → inquiries 表不存在 → 需要在 Content-Type Builder 里重新 Create
```

## 六、build-pages.js 失败

### 常见错误

| 错误信息 | 原因 | 解决 |
|---------|------|------|
| `获取设备数据失败: HTTP xxx` | Strapi 没启动或地址错 | 启动 Strapi，检查 STRAPI_URL |
| `Strapi 中没有设备数据` | 数据库空 | `npm run migrate` |
| `ENOENT: no such file or directory` | 模板文件缺失 | 确认 `equipment/_template.html` 存在 |
| `[slug] 渲染失败: ...` | 单条设备数据格式错误 | 后台编辑该设备，修复 JSON 字段 |

### 清理过期页面

```bash
npm run build-pages.js --prune
```

## 七、前端设备页显示异常

### 场景

| 现象 | 排查 |
|------|------|
| 所有设备页 404 | `build-pages.js` 没跑，或 `equipment/` 目录被清空 |
| 某一台 404 | slug 被删了但文件还在，或 slug 改了没重新 build |
| 页面有标题但没内容 | `window.__pageData.product` 为空 → 后台该条数据的 images/specs 字段格式错 |
| 画廊不显示 | images 字段是字符串而非数组 → 后台修复 JSON |
| 语言切换不生效 | 浏览器缓存旧的 `product-render.js` → `Ctrl+Shift+R` |

### 本地验证

```bash
# 1. 启动静态服务器
npm run serve

# 2. 打开
# http://localhost:3000/equipment/crawler-jaw.html
# http://localhost:3000/en/equipment/crawler-jaw.html
```

## 八、Admin 预览按钮灰色

### "Set up preview" 按钮显示

说明 `config/admin.js` 的 preview 配置未被加载。

```bash
# 检查 config/admin.js 是否有 preview.enabled: true
grep -A3 "preview:" backend/config/admin.js

# 修改后必须重启 Strapi
Ctrl+C → npm run develop
```

### 点击 "Open preview" 后 404

CLIENT_URL 配置的前端地址上没有对应的静态页。确认 `scripts/serve.js` 正在运行。

## 九、设备页语言切换问题

### 现象：第一次切英文失败，第二次才成功

这个问题已修复，详见 [本次会话记录] 和 `assets/i18n.js`、`assets/product-render.js` 的 git log。

### 现象：语言切换后部分文本没更新

可能是页面内嵌了 i18n.js 执行前就渲染好的内容。检查：

1. `assets/i18n.js` 引用是否有 `defer`（应该有，确保 DOMContentLoaded 后执行）
2. `product-render.js` 是否正确监听了 `minelink:lang` 事件

## 十、SQLite 数据库损坏

### 检测

```bash
node -e "const Database=require('better-sqlite3');const db=new Database('backend/.tmp/data.db');console.log(db.prepare('PRAGMA integrity_check').all());db.close();"
# 正常返回 [ { "integrity_check": "ok" } ]
```

### 恢复

```bash
# 1. 停止 Strapi
pm2 stop strapi   # 或 Ctrl+C

# 2. 用最近的备份替换
cp /opt/backups/strapi-YYYYMMDD.db backend/.tmp/data.db

# 3. 重启
npm run develop
```

### 重建（最兜底方案，数据丢失）

```bash
cd backend
rm -rf .tmp
npm run develop  # Strapi 自动创建空数据库
# 重新 migrate
npm run migrate
```

## 十一、性能问题

| 现象 | 排查 |
|------|------|
| Strapi develop 模式慢（正常） | develop 模式热更新开销大，生产用 start |
| GET /api/equipments 慢 | SQLite 加 31 条没问题；检查是否有 `public/uploads/` 磁盘空间不足 |
| build-pages.js 慢 | 62 个 HTML 文件，正常 1-3 秒；如果超 10 秒检查磁盘 I/O |
| 浏览器打开设备页慢 | 检查图片尺寸，压缩到 1920px 以下，用 WebP 格式 |
| PM2 CPU 100% | 看日志，通常是 SQLite 被锁（多个实例写） → 确保只有一个 Strapi 实例 |

## 十二、GitHub Pages 部署失败

| 现象 | 原因 | 解决 |
|------|------|------|
| Pages 显示 404 | 构建产物结构不对 | push 后在 `gh-pages` 分支看根目录有没有 index.html |
| 部分页面 404 | `en/equipment/` 目录没生成 | `build-pages.js` 检查 EN_EQUIPMENT_DIR 路径 |
| 旧内容没更新 | 浏览器缓存 | `Ctrl+Shift+R` 或加参数 `?v=2` |
