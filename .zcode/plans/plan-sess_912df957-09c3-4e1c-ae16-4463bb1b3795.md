# B2B 站点：全链路验证 + 手册重写计划

## 背景结论（检查代码的结果）

系统对"IP/端口随时变"的适应机制已经存在且设计良好，但文档没跟上：

- **机制**：`backend/.env` 的 `SITE_URL` 留空 → `scripts/build-pages.js` 把 `{{ORIGIN}}` 占位符写进所有静态页的 canonical/og:url 和 sitemap.xml → nginx（`/etc/nginx/sites-enabled/minelink` 第 9-11 行）用 `sub_filter` 在响应时替换为 `$scheme://$http_host`（访客实际访问的协议+主机+端口）。**换任何 IP/端口/域名都无需重建、无需改配置。**
- 前端 JS（询盘表单等）全部同源相对路径；Strapi 预览按钮动态取请求 Host。均与地址无关。
- **文档问题**：docs/17、18 均未提及该机制，且 §6/§12 仍推荐已过时的 `scripts/update-site-url.sh`——该脚本会把绝对地址写死进构建产物，**运行反而破坏动态机制**。
- **运行问题**：Strapi（:1337）当前未运行，后台与自动重建不可用（webhook-listener 正常）。

## 第一步：全链路验证（先做，把结果写进手册）

1. 启动 Strapi：项目根目录 `nohup npm start >> strapi-restart.log 2>&1 &`，确认 :1337 监听。

   - 设备页 canonical/og:url 同样按 Host 动态替换；
   - `/admin/` 后台 200、`/api/equipments` 正常；
